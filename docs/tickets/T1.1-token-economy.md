# T1.1 · Token economy for the agent workflow

> **Status:** ✅ Done
> **Phase:** Phase 1 (credibility)
> **Priority:** High
> **Date:** 2026-11-01
> **Depends on:** none
> **Origin:** request (written after the fact: the work existed uncommitted before the backlog did)

## Description

A ticket run read the whole backlog, pasted the output of every gate and launched review subagents
for diffs of three lines. Each of those costs tokens without improving the result.

## Technical Scope

1. `workflow_check.py`: `context`, `review-plan`, `gates --run`, the `[efficiency]` settings.
2. Review agents: capped, one line per finding; `test-auditor` on a cheaper model.
3. Out of scope: deciding the amount of process a change needs (T1.5).

## Acceptance Criteria

- `context` prints a compact brief with dependency status. test: test_context_is_a_compact_brief_with_dependency_status
- `review-plan` skips subagents for tiny or docs-only diffs. test: test_tiny_or_docs_only_change_is_self_reviewed
- A changed line is counted once. test: test_a_modified_line_is_counted_once
- A sensitive change always gets the security reviewer. test: test_a_sensitive_change_always_gets_the_security_reviewer
- `gates --run` logs the full output and prints one line per gate. test: test_passing_gate_costs_one_line_and_its_output_goes_to_a_log

## Risks

The line threshold is a proxy for risk; T1.5 replaces it with lanes.
