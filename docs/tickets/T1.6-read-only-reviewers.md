# T1.6 · Review agents that really are read-only

> **Status:** ✅ Done
> **Phase:** Phase 1 (credibility)
> **Priority:** Medium
> **Date:** 2026-11-01
> **Depends on:** T1.5
> **Origin:** audit ("read-only" was a request in the prompt, not a permission: the agents had Bash)

## Description

The review agents declared themselves read-only but had `Bash`, which can edit, commit or push.

## Technical Scope

1. Remove `Bash` from `reviewer` and `security-reviewer`; `review-plan --write-diff` writes the diff
   to `.agents/.cache/review/diff.patch` for them to read; the gates already ran the tests.
2. `test-auditor` keeps its shell: mutation testing (which caught weak tests in every review of this
   phase) needs to run code. It stops claiming to be read-only, mutates only in a disposable
   worktree, and `ticket-runner` compares `workflow_check.py fingerprint` (a content hash of HEAD,
   the working tree and untracked files) before and after it. `git status` was rejected in review:
   further edits to an already-modified file leave it unchanged.
4. `review-plan --write-diff` writes only through real directories (`O_NOFOLLOW`), never runs an
   external diff or textconv driver, is binary-safe, handles unusual names and repositories without
   commits, and refuses a `--base` that looks like an option. Gate logs use the same safe writer.
3. The hygiene test forbids tools that write in every review agent, anything beyond Read/Grep/Glob
   in the read-only ones, and checks that each agent's prose matches its tools.

## Acceptance Criteria

- No review agent has a writing tool; reviewer and security-reviewer have nothing beyond Read, Grep, Glob. test: test_every_skill_agent_and_command_has_valid_frontmatter
- Each agent's prose matches its tools (read-only, or disposable worktree). test: test_the_prose_of_each_reviewer_matches_its_tools
- `review-plan --write-diff` writes the full diff, untracked files included. test: test_review_plan_writes_the_diff_for_reviewers
- Added after the security review: a symlinked cache is refused (test_write_diff_refuses_a_symlinked_cache); an
  external diff driver never runs (test_write_diff_never_runs_an_external_diff); `--base`, unusual names, binaries
  and repositories without commits (test_write_diff_covers_base_names_binaries_and_no_commits); a further edit of a
  modified file changes the fingerprint (test_fingerprint_sees_a_further_edit); an option as `--base` is refused
  (test_an_option_is_not_a_base).

## Risks

Requires security review. Found in review, out of scope (T1.7): a repository's own git config can
make `git diff` run a filter (`filter.<x>.clean`); this predates T1.6. Reviewers can no longer run a check to confirm a finding; they rely on the
gate logs and report «not verified» otherwise. `test-auditor` can still change files in principle:
the fingerprint detects a change of content or of the index, it does not prevent it, and does not
cover ignored files or the inside of `.git` (its config included).
