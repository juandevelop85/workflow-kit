# T1.7 · Run git with a neutral configuration

> **Status:** ⏳ Pending
> **Phase:** Phase 1 (credibility)
> **Priority:** Medium
> **Date:** 2026-11-01
> **Depends on:** T1.6
> **Origin:** security review of T1.6

## Description

The threat model says a hostile repository controls its git configuration, but the checker only
switches off `core.fsmonitor`. A repository-local `filter.<x>.clean` plus a committed `.gitattributes`
makes `git diff` (and so `numstat`, `changed_files`, `review-plan --write-diff` and `fingerprint`)
run a command. `diff.external` and `textconv` are already neutralised (T1.6); filters are not.

## Technical Scope

1. Run git with filters neutralised (e.g. `-c filter.<name>.clean=` for every filter named in
   `.gitattributes`, or a temporary index and `GIT_CONFIG_NOSYSTEM`/`GIT_CONFIG_GLOBAL=/dev/null`),
   or state in the threat model that repository-local git config is trusted, and why.
2. Out of scope: hooks (the checker never commits).

## Acceptance Criteria

- A `filter.<x>.clean` configured by the repository never runs during `check`, `classify`,
  `review-plan --write-diff` or `fingerprint`. test: test_git_filters_never_run

## Risks

Requires security review. Neutralising filters can change what `git diff` reports for files that
rely on them (e.g. LFS pointers): the diff must stay readable.
